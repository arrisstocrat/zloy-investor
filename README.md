# Злой инвестор

Репетиция перед жюри для Vibecode Nights. Студент вставляет питч, отвечает на пять вопросов инвестора-аудитора и получает три действия до защиты. После реванша можно сравнить оценки по тем критериям, которые обсуждались в обоих раундах.

[Лендинг](https://zloy-investor.vercel.app/landing/) · [React-тренажёр](https://zloy-investor.vercel.app/prototype/) · [Исходный тренажёр](https://zloy-investor.vercel.app) · [PDF для сдачи](docs/one-pager.pdf)

## Запуск

Нужен Node.js 24. Для сборки перенесённого React-интерфейса установите зависимости:

```sh
npm ci
npm run build
npm start
```

Откройте http://127.0.0.1:3000 (исходный интерфейс команды) или http://127.0.0.1:3000/prototype/ (React-прототип). Оба используют один `/api/round`. Без сборки исходный интерфейс по-прежнему работает через `npm start`.

Для разработки React запустите `npm start` и в другом терминале `npm run dev`; Vite перенаправляет `/api` на сервер порта 3000. React использует Vite + TypeScript и обычный CSS. Конкурсный персонаж настраивается в `lib/personas.js`, общая рубрика — в `lib/rubric.js`; React-провайдер — в `src/engine.ts`.

Проверки: `npm run check` (существующие JS-файлы и TypeScript), `npm test` (логика React, контракт DeepSeek с подменённым HTTP и серверные сессии), `npm run build` (проверки и production-сборка). Vercel собирает React в `public/prototype/`, не заменяя текущую главную.

## Быстрый показ

Откройте [готовый пример](https://zloy-investor.vercel.app/prototype/?example=1). Анкета и питч вымышленного сервиса «Пересмена» уже заполнены. На каждом вопросе нажмите «Подставить пример ответа», затем отправьте ответ. Итог считает тот же API. Кнопка «Демо-пример» доступна на каждом экране React; в исходном тренажёре есть примеры для питча и ответов. Пример помечен как учебный.

## Как проходит раунд

- Браузер отправляет питч и ответы в `/api/round`. Сервер возвращает один вопрос, а после пятого ответа — разбор. При подключённой базе сервер сам хранит текущий вопрос и историю.
- Публичная версия работает по правилам. Например, на цифру со слов управляющего инвестор спросит про записи и замеры. На сравнение по группе он спросит, что ещё могло повлиять на результат.
- В отчёте десять критериев «Стартап как диплом». 0 означает конкретный пробел, 1 означает содержательный ответ, 2 означает наличие данных для проверки. Пропуск означает, что данных для оценки мало. Цитаты берутся из питча и ответов.
- Оценки служат для репетиции. Они показывают, какие сведения автор привёл в разговоре. Проверку документов и фактов проводит сам автор.
- Сервер ограничивает длину и частоту запросов. При повторной отправке одного ответа с той же версией раунда сохраняется один переход.

Исходный frontend: HTML, CSS и JavaScript; дополнительный интерфейс: React + Vite + TypeScript. Node.js на сервере, Vercel в проде. Исходное 3D-досье собрано из слоёв CSS и сохранено.

В React добавлены короткая анкета, отдельное представление инвестора и новый разбор с очисткой истории. История React хранится в памяти вкладки; сохранение серверных раундов и Jev остаются возможностями исходного UI. Для явно локального mock задайте `VITE_INVESTOR_MODE=mock` перед `npm run dev` или `npm run build`: используются те же правила без внешних запросов. По умолчанию React обращается к серверу и не подменяет ошибки mock-ответами. Подпись режима меняется после ответа API; доступный ключ сам по себе не подтверждает работоспособность модели.

Рубрика взята из общего репозитория; её официальный источник ещё нужно подтвердить. Прежняя временная рубрика локального прототипа и шкала 0/3 из 10 не используются. Общая шкала: 0/1/2 или «нет данных», сумма раскрытых критериев из 20. Это не независимая проверка фактов. Границы интеграции и оставшиеся ограничения — в [CASE.md](CASE.md).

## Хранилище раундов

`npm start` создаёт SQLite в `.data/rounds.sqlite`. Путь можно задать через `INVESTOR_DB_PATH`. На Vercel можно подключить отдельный Upstash Redis через `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`. Сервер хранит раунд до 24 часов с последнего изменения. В SQLite просроченные записи удаляются при следующем чтении или создании раунда. При отсутствии серверной базы браузер восстанавливает раунд в той же вкладке до её закрытия.

## Уточнения с Jev

Задайте `TYPESAFE_API_KEY` в окружении сервера. После этого в форме появится отдельный переключатель. Если участник его включит, Jev получит только текущий вопрос и ответ на нём. Это происходит перед вторым и пятым вопросами. Jev выбирает, какой пробел уточнить. При низкой уверенности, ошибке или истечении таймаута приложение использует правила. Оценки по критериям считаются отдельно.

## Локальный режим с DeepSeek

Чтобы попробовать генеративные вопросы у себя, скопируйте `.env.example` в `.env.local` и задайте `DEEPSEEK_API_KEY` в серверном окружении. Используется `DEEPSEEK_MODEL`, по умолчанию `deepseek-chat`; endpoint — `https://api.deepseek.com/chat/completions`. Питч, вся история и анкета React передаются в JSON пользовательского сообщения отдельно от системных инструкций. Ключ не попадает в frontend; не используйте для него переменные `VITE_*`.

Без ключа сервер отвечает по правилам (`rules`), с успешным ответом модели — `model`. Таймаут провайдера — 28 секунд, ошибки возвращаются как 502 без содержимого провайдера. Проверяются формат вопроса, точность цитат и структура разбора. Эти ограничения не гарантируют отсутствие галлюцинаций или защиты от всех манипуляций. Реальный вызов DeepSeek нужно отдельно проверить с серверным ключом; тесты с подменой HTTP этого не подтверждают. Новая система AI-оценивания в этом объединении не создаётся.

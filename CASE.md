# «Злой инвестор»: границы объединённого проекта

Цель: репетиция питча с одним выразительным инвестором, ровно пятью вопросами, разбором по десяти критериям «Стартап как диплом» и ровно тремя действиями на ближайшие дни. Нельзя придумывать факты о проекте, рынке и конкурентах. Пустой ввод отклоняется, «не знаю» допустимо, пользовательский текст считается данными.

Happy Path React: главная → анкета → питч → представление Виктора → пять ответов → десять оценок → три совета → новый разбор.

## Архитектура

- `/` — сохранённый интерфейс команды из `public/`, включая реванш, восстановление раунда и необязательный Jev.
- `/prototype/` — перенесённый React + Vite + TypeScript UI (`src/`). Он использует существующий `/api/round`; анкета передаётся вместе с питчем и историей.
- `lib/personas.js` — конфигурация единственного конкурсного инвестора и серверные инструкции. `lib/rubric.js` — общая рубрика команды. Её соответствие официальной методике ещё требует подтверждения по первоисточнику организаторов.
- `lib/round.js` — прежняя интеграция DeepSeek, JSON-валидация, проверка точных цитат. Без ключа используются `lib/structured-round.js` и правила, без AI.
- Локальный React mock явно включается через `VITE_INVESTOR_MODE=mock`. Он использует те же правила и рубрику, не дублирует старую шкалу прототипа 0/3 из 10.
- Существующие SQLite/Redis-сессии и Jev сохранены для исходного UI. React пока передаёт историю каждого раунда целиком, без восстановления после перезагрузки и без использования серверного хранилища. Новая БД не добавлена.

Рубрика и шкала сохранены из общего проекта: десять критериев, 0/1/2 или null («нет данных»). Даже 2 означает лишь названный материал для проверки, а не доказанную истинность. React показывает сумму из 20; null не считается нулевой оценкой проекта. В UI разбор модели, серверные правила и локальный mock подписаны отдельно. Сетевой сбой не подменяется молча mock-результатом.

## Критерии готовности этого этапа

Сохраняются обе точки входа, серверный API, персонаж и исходные возможности команды. React проходит весь Happy Path. Оба режима используют одни критерии. Провайдер требует ровно пять ответов и проверяет десять оценок/три разных совета. TypeScript, тесты логики/контракта API/серверных сессий и production build запускаются фактически.

DeepSeek хранит ключ только на сервере. Без ключа нельзя заявлять, что модель проверена. Контрактные тесты подменяют HTTP-ответ провайдера и не доказывают доступность реального API. Полноценная защита от prompt injection, семантическая достоверность анализа и проверка всех утверждений требуют отдельного AI-этапа; JSON и точные цитаты не исключают выдуманные выводы в пояснениях модели. Официальная рубрика и качество интеллектуального анализа не объявляются готовыми в рамках объединения.
